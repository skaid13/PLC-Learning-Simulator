# PLC 实验教学与仿真系统

面向 PLC 零基础学生的本地教学工作台。版本 **1.4.0-preview.1（本机试学版）**。React + TypeScript + Vite + CSS + SVG，逻辑在浏览器内执行，无服务器数据库、登录、付费 API 或实体 PLC 依赖。安装依赖后，学习与仿真可以离线运行。

依据用户提供的《PLC实验箱实验指导书0827.docx》，参考其中的 Rockwell **2080-LC50-24QVB** 和 BDT-PLC-A 实验箱。`SIM_*` 为本软件教学变量，`I-xx / O-xx` 为指导书端子标记。本软件不是官方 PLC 仿真器，JSON 不能下载到实体 PLC。真实指令语义和运动轴能力未作官方核验；支持的行为以 [执行规则](docs/ENGINE_RULES.md) 为准。

## 1.4 第一课试学版：从看懂到独立完成

默认进入唯一的新手学习首页，点击“开始第一课：按钮亮灯”。按照 **认识对象 → 观察示例 → 跟随搭建 → 补全程序 → 独立搭建 → 变化任务** 学习；每阶段明确当前位置、动作、原因和预期结果。按钮、触点、线圈和灯先逐个解释，再观察公共扫描引擎运行的示例。

搭建时先显示编辑器，检查结构后展开按钮/预测/扫描区。先预测亮或灭，再单步；接通和断开两种实际扫描都符合要求才能继续。错误预测给出实际输入、条件和结果；修改程序会复位并清除验证。独立练习按需打开三层提示，最终把常开改为常闭，验证相反规则。

上方“知识工具箱”统一说明输入/输出/内部变量、常开/常闭、线圈、串并联、保持、时间、计数、边沿和运行操作的用途、选择理由、区别、例子、错误与验证方法。原十课阅读、三个入门项目和11个正式实验从“课程与实验”进入；原有完整工作台仍可自由编辑。

教学草稿使用独立键 `plc-learning:first-lesson:v1`，每阶段各自保存，不覆盖原 `plc-learning-projects-v1`。退出保留草稿，刷新后从首页继续原阶段；不自动恢复运行或本次扫描证据。程序可导出为原schemaVersion 1格式；重建本阶段前确认并下载备份，可撤销。损坏教学记录保留原文，保存失败显示反馈并允许继续。

本轮25个测试文件155项、类型/构建、实际六阶段页面操作、常开/常闭变式、恢复、JSON下载及桌面/窄屏检查通过。Windows实机、此次原生JSON导入和真实零基础试学未验收。**等待用户试学第一课后再推广新流程与上传GitHub**；当前远程仍为已备份的1.3.0，本地分支 `codex/learning-path-1.4`。阶段证据与恢复方式见 [1.4学习主线记录](docs/LEARNING_PATH_1.4.md)。

## 1.3.0 文字基础课堂

点击工作台上方“文字基础课堂”，或入门地图的“基础课堂：从零打基础”。独立阅读窗口包含十课：PLC 的作用、变量、扫描、触点/线圈、串并联、保持、定时、上升沿/计数、顺序控制和调试验收。

每课按学习目标、正文讲解、逐步例子、自查问题/展开答案、易错点和实践入口组织。不需要先会电路或编程。章节可自由回顾，阅读位置及已读记录单独保存；已读不代表掌握。跳转项目保留各实验已有草稿。

建议先读第1～4课做按钮亮灯，第5课做停止条件，第7课做延时，第6/8/9课帮助衔接完整实验。最后用第10课的方法做独立变式验收。软件测试通过不能替代零基础学生的实际学习验证，也不能保证每个人独立完成全部11个实验。

本版包含1.2.0的全部功能，当前已验证144项测试。本机导入与实测记录见 [1.3.0 本机更新记录](docs/UPDATE_IMPORT_1.3.0.md)，课程设计见 [文字基础课堂更新记录](docs/FOUNDATION_UPGRADE.md)。

## 双击启动（已安装 Node.js 时）

**Mac：双击桌面的「PLC实验教学与仿真系统 1.4 试学版.command」快捷方式。** 也可以在项目文件夹双击 `启动PLC学习工作台.command`。入口自动找到项目，启动本机服务并打开默认浏览器；如果当前正式服务已经运行，会复用服务，不重复启动。

新启动的服务需要保留终端窗口。结束学习后在该终端按 `Ctrl+C` 停止；已运行服务复用时，快捷方式自身会正常结束。Mac 项目内启动文件需要可执行权限；复制源码后如提示权限问题，在项目目录执行 `chmod +x 启动PLC学习工作台.command`。

**Windows：双击项目文件夹的 `启动PLC学习工作台.bat`。** 同样需要 Node.js 和已经构建好的 `dist`；需要桌面快捷方式时，右键此文件选择“发送到 → 桌面快捷方式”（或“显示更多选项”后找到）。Windows 入口尚未在 Windows 实机测试。

快捷入口不自动安装依赖或修改学生程序。缺少 Node.js / 正式构建或端口被其它服务占用时，会显示具体说明。项目内入口采用相对位置，移动项目后仍可使用；Mac 桌面链接指向本次项目位置，移动项目后需重新建立桌面链接。

## 首次安装（macOS / Apple M4）

安装 Node.js 22.12 或以上版本（附带 npm）。终端进入项目文件夹后运行：

```sh
npm ci
npm run dev
```

依赖首次安装需要联网。看到 Vite 打印的地址后，在浏览器打开，通常是 `http://127.0.0.1:5173/`。端口被占用时以终端实际输出为准。保持终端运行，按 `Ctrl+C` 停止。

## 首次安装（Windows）

安装相同要求的 Node.js，在项目文件夹空白处打开 PowerShell 或命令提示符：

```powershell
npm.cmd ci
npm.cmd run dev
```

`npm.cmd` 可避免 PowerShell 的脚本执行策略阻止 `npm.ps1`。代码和 npm 脚本共用一套，没有 Windows 专用组件。Mac 的 `node_modules` 含平台相关开发依赖，不能直接当作 Windows 依赖使用，应在 Windows 重新 `npm.cmd ci`。

**Windows 实机运行尚未验证。** 已采用跨平台路径和 Node 标准库启动方式，不能据此声称 Windows 已验收。

## 正式构建和离线运行

```sh
npm run build
npm start
```

Windows 使用 `npm.cmd run build`、`npm.cmd start`。打开 `http://127.0.0.1:4173/`。不要直接双击 `dist/index.html`，ES 模块需要通过本地 HTTP 服务加载。

`npm start` 通过 `scripts/serve.mjs` 使用 Node 标准库提供 `dist`，运行时不需要 npm 依赖或联网。只监听本机 `127.0.0.1`。源代码更新后需重新构建才能更新正式版。若 4173 被占用，可在 macOS 使用 `PORT=4174 npm start`，PowerShell 使用 `$env:PORT=4174` 后再执行 `npm.cmd start`。

跨电脑的轻量离线版本只需要 **`dist`、`scripts`、`package.json`** 和目标电脑已安装的 Node.js；在这三项的共同目录执行 `npm start`。如需双击启动，一并复制项目根目录的 `.command` / `.bat` 启动文件。需要开发或测试时，复制完整源码及锁文件，并在目标系统安装依赖。

## 从零开始

1. 双击启动后，在学习首页点击“开始第一课：按钮亮灯”；返回学习可显示“继续第一课”。
2. 依次点按钮、触点、线圈、灯四张对象卡，读用途并回答问题。尚未认识时不用画线路。
3. 观察示例：接通亮灯按钮，先预测，再点击“预测后单步扫描”；断开后再预测/扫描，比较两种结果。
4. 跟随搭建：按当前任务高亮选择工具、放置元件、选择变量，再检查结构和实际验证。补全阶段只缺一个线圈；独立阶段从空白开始。
5. 变化任务把自己的独立程序复制到新阶段，要求断开亮、接通灭；先自己判断，不确定时再打开知识工具箱或分级提示。
6. 学完第一课进入停止条件、延时亮灯，再选择正式实验。其余实验继续使用分层课程、引导和逐网络搭建清单，暂未推广六阶段新流程。
7. 原有程序从“完整工作台”打开，保存、JSON导入导出、撤销重做、变量管理和参考程序保持。返回第一课保留工作台编辑历史；离开会停止连续运行。

停止保留最后状态，复位重置运行值和装置但保留程序。重建会替换程序，必须先确认和下载备份。程序编辑会复位；改变输入后需要新的扫描。教学解释和颜色以本软件实际轨迹为依据，不是实体PLC工程或真实电流。

## 保存、备份与 Mac/Windows 迁移

- 每次程序编辑自动写入当前浏览器的 localStorage；“保存草稿”手动再保存一次。状态区显示成功时间或失败原因。
- 浏览器、地址和端口隔离存储：`5173` 和 `4173` 的草稿不同；隐私模式或清理浏览器数据会失去本地保存。
- 在 Mac 点击“导出 JSON”，把文件复制到 Windows，在相同软件中点击“导入 JSON”，选择文件并确认。运行值、物理状态和撤销历史不导出，避免重新打开时自动运行。
- JSON 包含 schemaVersion、实验 ID、变量、网络、支路和指令；只用于本仿真器。限制 1 MB、500 个网络、500 个变量、每网络最多 8 支路、每支路最多 4 触点。
- 导入拒绝损坏结构、未知版本、重复标识或不匹配的物理 I/O。未绑定的编辑草稿可以导入，但需补齐后才能运行。
- 损坏的本地存储不会在打开页面时覆盖，提供原文备份下载；开始编辑后会用新的工作区自动保存。存储空间不足时请立即导出 JSON。
- 1.3.0 保持原 schemaVersion 1 程序格式，无需迁移；新增小项目JSON需1.2.0及以上版本。教学章节/引导进度单独保存在当前浏览器，不包含在程序 JSON 中；刷新不自动恢复运行。
- 撤销/重做只在当前打开的页面内保留，每实验最多 50 步。复制/粘贴网络在当前实验内使用，复制后应检查普通线圈是否重复绑定。

上传保持原始文件目录和现有 Git 历史。现有GitHub仓库由用户主动设为Public，本轮保持可见性；1.4试学版等待验收后才上传。只备份源码、配置、锁文件、测试、启动脚本和文档，包括原始 DOCX；`node_modules`、`dist`、测试输出和凭据由 `.gitignore` 排除，不会从本机删除。

从 GitHub 获取源码后，在项目目录执行 `npm ci`、`npm run build`，再双击对应系统启动入口，或运行 `npm start`。Windows 使用对应的 `npm.cmd` 命令。`dist` 不在仓库中，所以刚获取的源码需要先构建。

学生在浏览器 localStorage 中的草稿不属于源码目录，不能通过 Git 自动备份。需要一并保留自己的梯形图时，请先通过工作台导出 JSON，再将所需文件保存到项目内的 `student-programs/` 后提交；该目录及 JSON 格式不会被忽略。不要把含个人凭据的文件放入其中。
